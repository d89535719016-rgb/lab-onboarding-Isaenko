# Отчет по практическому занятию №7. Анализ потоков данных, дизассемблирование и линтинг.

## 1. Анализ потоков данных (DFA)

### 1.1. Таблица Def-Use цепочек

| Переменная | Def | Use |
|---|---|---|
| log_entry | строка 2, строка 10 | строка 13 |
| status | строка 5 (только если amount > 0) | строка 10, строка 15 |
| balance | строка 6 | строка 7 |
| new_balance | строка 7 | строка 8 |
| file | строка 12 | строка 13 |

### 1.2. Выявленные дефекты

- Дефект 1 (Неинициализированная переменная): status определяется только внутри if amount > 0 (строка 5). Если amount <= 0, в строках 10 и 15 переменная используется без определения, возникает UnboundLocalError.
- Дефект 2 (Мертвое присваивание): значение log_entry = "Start processing" (строка 2) никогда не читается, в строке 10 переменная перезаписывается.
- Дефект 3 (Утечка ресурса): файл открывается в строке 12, но file.close() не вызывается и with не используется, дескриптор остается занятым.

## 2. Дизассемблирование

### 2.1. Восстановленный код на Python

    total = 0
    i = 1
    while i <= 10:
        total += i
        i += 1

### 2.2. Пояснение логики

-4(%rbp) хранит аккумулятор (total = 0), -8(%rbp) хранит счетчик (i = 1). jmp .L2 переходит к проверке cmpl $10 / jle: пока i <= 10, выполняется тело цикла .L3 (total += i, i += 1). После цикла total копируется в %eax. Фрагмент считает сумму чисел от 1 до 10, результат 55.

## 3. Деобфускация

### 3.1. Расшифрованная строка

    import os; os.system('rm -rf /')

### 3.2. Анализ угрозы

exec выполняет расшифрованный код, который запускает rm -rf /: рекурсивное принудительное удаление всех файлов от корня файловой системы. Будут уничтожены ОС, программы и данные, система перестанет загружаться. Base64 только скрывает назначение кода.

### 3.3. Методы защиты

- не использовать exec и eval для непроверенных данных;
- валидация входных данных;
- статический анализ в CI (flake8, bandit);
- код-ревью подозрительных Base64-строк;
- запуск с минимальными правами, песочница;
- резервное копирование.
